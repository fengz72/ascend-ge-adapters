## 修改与执行路径

修改现有 `third_party/custom_development_code/fusion_pass/WeightNzAndMatMulV3Pass`，注册名不变。
原实现只匹配MatMul/MatMulV2，A5配置也没有选择该依赖；新增对已有MatMulV3的支持：

1. 对独占常量的FP16/BF16、静态正二维ND右矩阵、transpose_x2=false完成CPU侧预排布，NZ为[N1,K1,16,c0]；激活与输出保持ND。
2. 检查buffer大小、dtype、形状及乘积溢出，尾部补零；共享消费者、同节点输入端口别名、已是NZ、不支持的格式/类型/形状均跳过。
3. 重建MatMulV3，继承transpose_x1/transpose_x2、offset_x、opImplMode、可选输入及数据/控制边；重新选择NZ实现，避免携带ND kernel匹配/ACLNN fallback缓存。
4. A5已有V3由GE自行选择核类型；保留旧MatMul/MatMulV2路径的A3调度约定，不修改原生GE执行器、前端、输入池、AIR或runtime。

首个原地更新试验虽然转换169个权重且编译成功，执行时仍进入ND的aclnnAddmm，报
`Expected 2 dimension input, but got mat2 with sizes [8, 56, 16, 16]`。
重建节点后跑通；该失败保存在probe/native.log与probe-inplace-failure.plog，不能作为性能结果。

Profiling逐图验证169个MatMul、24个attention。四组采集中，168个主干投影均保持16个block，裁剪后的输出头均为1个block；
NZ组169个权重的Input Formats均含FRACTAL_NZ，kernel由`MatMulV3_ND_ND_...`切换为`MatMulV3_ND_NZ_...`。
**正式阶段新增TransData数为0**，没有把权重格式转换挪到每次请求。
ND组存在aclnnMm/aclnnAddmm Host API，NZ组相应调用不再出现，属于执行路径改变；不能把全部吞吐收益都归到MTE2。
