# OPT-011：仅融合 attention/output 的24组 Add＋LayerNorm

## 1. 身份与状态

2026-10-26 主控分配；100/hejun-cann9-bge、逻辑2、GE Session mode=0。父配置为已通过正确性压力的FP32八实例半核12|24（OPT-009），不继承OPT-010全48处融合结果。V3源码与独立so已隔离构建，状态：设备验证待执行；若实际启动则占12组配置中的最后一组。

## 2. 问题与假设

同机同固定case的 GE profiling 对齐30次执行后发现：24个attention/output位置的Add+LN片段均值8.875→4.318μs，而24个FFN output位置4.590→4.895μs。全48处融合虽使目标kernel累计时间下降31.58%，但整模型单实例吞吐未呈稳定提升。假设只保留前24处可减少不利位置的额外开销，需通过八实例半核的完整精度及端到端吞吐实测验证；局部kernel时间不能代替收益。

## 3. 实现与回退

新插件 `libbge_add_layernorm_attention_v3.so` 只匹配layer.0–23的attention/output残差Add+LN；FFN output、embedding及未知scope保持原图。V2源码/so和原图不修改。CANN9真实13项GE CPU图契约、11项preload过滤、3项native/child环境集成、`ldd -r`与本地数值语义检查均PASS；设备实际命中次数、完整输出、吞吐尚待检验。仅给native子进程预加载V3，保留tcmalloc；回退移除V3恢复OPT-009。

## 4. 比较条件

与同机同设备同固定case的OPT-009八实例半核父配置对照。先随机五例≥2000请求全量FP32 scores和Top10 ID+1/顺序/分数，8×5组合各≥20，检查实际融合命中24处；后做固定case-0002至少30秒/2000请求搜索。统一闭环单在途、H2D+GE同步+完整D2H计时；性能轮关闭capture/profiling。双芯片持锁前后门禁与轮内NPU/Host资源采样。若搜索显示可靠收益才考虑冻结正式两场景三轮及随机10分钟稳定性。

## 6. 分析与决策

候选不改模型输入输出、dtype、expected或误差阈值。精度、接口、清理或外部占用任一失败则不接纳；吞吐收益需大于3%且超过轮间波动，不因kernel局部改善自动接纳。开始前检查设备总预算仍可保留至少3000秒最终验收；预算不足记录未运行，不耗尽最后配置名额。
