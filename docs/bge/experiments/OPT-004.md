# OPT-004：限定融合插件到native进程并保留allocator（V2）

## 1. 身份与状态

2026-10-26；主控分配，SE/开发实现或配置，测试独立核对。父版本为原FP32全核单实例，GE Session mode=0，逻辑设备10（NPU5/Chip0，PCI0000:89:00.0）。不纳入默认吞吐配置：有效搜索QPS观察-2.02%，在已测波动内，未证明吞吐收益。

## 2. 问题与假设

口径同 [README.md](README.md) 第 2 节。本项检验限定到 native 进程的 V2 融合插件能否提高包含输入输出搬运的成功吞吐；不由算子数量或数据类型推算收益。

## 3. 实现与回退

融合数学与48个命中不变。V2 SHA256=76ea9fb0f1800369b023e22d71298e508dcfaa6f69f34bcf952af4a1b5fa48ed。plan.runtime_env只给native子进程追加插件并保留/usr/lib64/libtcmalloc.so.4.5.16；constructor仅从未来子进程LD_PRELOAD移除自身，保留其它库。冻结主binary不变。

源模型/权重、样例、expected 与阈值不变（口径见 [README.md](README.md) 第 2 节）。测量 binary SHA256=8efca50a62a7f569032345259d6e7813da428023903e4674d77de92bc7ac630d。回退到原 FP32、全核、instances=1、不加载插件。

## 4. 比较条件

口径同 [README.md](README.md) 第 2 节。本节为 30 秒且 ≥2000 请求的搜索，capture/profiling=false；压力采集另做，采集数字不作性能值；相对差值只是搜索观察，无统计显著性声明。

## 6. 分析与决策

V1清理问题在V2的两次执行未复现，环境修复可保留为实验交付件；不能因此断言特定遗留子进程根因。搜索p99较小是不同容量点观察，不能解释成同负载延迟收益。未执行此配置三轮正式性能及10分钟稳定性。

不纳入默认吞吐配置：有效搜索QPS观察-2.02%，在已测波动内，未证明吞吐收益。汇总规则见 [README.md](README.md) 第 2 节。
