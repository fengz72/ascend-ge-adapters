## 2. 问题与假设

OPT-009 固定 case 单轮搜索为609.358298 QPS，较本机八实例全核463.246410 QPS高31.54%，因此选择半核为并发父配置。融合 V2 可将48组残差 Add+LayerNorm变为AddLayerNorm；单实例同机交错搜索未证明吞吐收益，但限核并发下的调度和资源效应可能不同。仅把“组合是否提升成功吞吐”作为可检验假设，不把单次profiling kernel耗时当整模型性能结论。

## 3. 实现与回退

保持八实例、12|24、原始FP32输入输出、mode=0、完整D2H计时、样例、expected与门槛；仅向native runtime加载已验证融合 V2 插件，形成48处AddLayerNorm。回退移除插件，恢复OPT-009；原图和融合源图分别保留。插件只能在native子进程注入，外层保持allocator预加载。

## 4. 比较条件

先随机五例2000请求全量输出压力，覆盖8×5实例与case且各≥20；再固定case-0002 30秒、至少2000成功请求搜索。与同机同设备同case父配置比较成功QPS及p50/p99；性能轮capture/profiling关闭、闭环每实例单在途、计时包括H2D/GE同步/D2H。两芯片持锁前后门禁及轮内资源采样均记录；失败、超时、清理或外部负载异常不产生有效性能数值。只做一次联合候选，后续选择冻结配置并做双场景各三轮正式复测及600秒稳定性。
