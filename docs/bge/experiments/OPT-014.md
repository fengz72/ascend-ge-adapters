# OPT-014：原图FP32十六实例、每算子12|24核

## 1. 身份与状态

2026-10-27分配。父配置为100本机原图FP32、GE mode=0、8实例、每算子`12|24`核上限；目标配置改为16实例，其余图、runner、输入、精度与设备身份不变。状态：固定case两轮搜索通过，**不接纳**。

## 2. 问题与假设

10、12实例搜索分别586.098、597.772QPS，尚未超过8实例586.387QPS正式中位数的测量波动门槛。16实例可检验更高并发是否继续增加成功吞吐，或因GE调度竞争使p99上升而QPS停滞。99机器的16实例全核SIGKILL原因未明，本次为100机器的半核配置，不能沿用旧结论。

## 3. 实现与回退

仅实例数改为16。保持原始30个Slice图、FP32、GE mode=0、`aicore_num=12|24`、无自定义融合插件。回退到已验收的8实例配置。

## 4. 比较条件

100逻辑设备2、固定`case-0000`、batch1，每实例单在途，预热10次。计时包含H2D、GE完成同步和全量D2H，无capture/profiling；搜索至少30秒/2000请求。记录HBM和Host RSS峰值、加载/退出状态，和8/10/12实例对照时注明测量级别。

## 6. 分析与决策

两轮分别30.002413/30.002063秒、17551/17640窗口成功、0错误，计划/输入/二进制身份、独立性能重算和作业释放检查通过。中位相对8实例正式中位数仅+0.015%，比12实例两轮中位下降2.03%，p99显著升高；HBM仍有容量余量，不能解释为显存上限。确认本搜索范围的吞吐平台/回落，本项**不接纳**，不继续盲目增加到20实例。
