## 2. 问题与假设

- 瓶颈与证据：[FP16+FIAS 图和 profiling](../analysis/fias-fp16-graph-profile-20261029.md)显示每请求仍运行 6 个候选常量链 kernel，累计 334.96 µs kernel 时间。
- 优化假设：GE 编图时由三个固定权重计算归一化表 C 与投影表 P，以两个 Const 替代原链；不能把 kernel 时间直接当作端到端收益。
- 方法来源：项目 `npu-model-workflow` 与 `npu-performance-analysis` 技能；当前 GE FIAS 自定义 pass 作为改图 API 参考。

## 3. 实现与回退

- 实际变更与作用层：GE 编图阶段；不修改源 ONNX、不加缓存。
- 代码、图和配置差异：`tools/bge_candidate_precompute/bge_candidate_precompute_pass.cpp`、`README.md`、`models/bge/run_experimental.sh`；构建期从三个 FP32 Const 计算两张表，不缓存、不修改 ONNX。与结构 FIAS SO 一起预加载。
- 生效证据：CANN 9.0.0 容器内 `g++` 构建 SO 退出 0；`test_precompute` 和 `test_graph_rewrite` 退出 0，分别检查数值、结构匹配、三路重接与旧节点移除。原始导出 ONNX 的仅编译检查退出 0。2026-10-30 的预计算性能图共 20 个 graphId，全部 `matched=1`、`replaced=1 rows=10112 width=512 tables_bytes=41418752`，结构 FIAS 均命中 24 层；20 图全部编译、加载、执行成功。尚未单独采集最终执行图或 profiling，不把 pass 命中直接当作逐请求 kernel 时间证据。
- 回退方法：运行时不预加载本 pass，继续使用同一原始 ONNX 与 FIAS pass。

## 6. 分析与决策

- 性能判断：固定 case-0000 两个顺序相反的同卡对照均显示 QPS 增益，最小配对增幅 7.461%，大于两轮基线自身约 3.43% 的相对极差；合并 QPS +9.797%。平均延迟下降，但 p99 一轮下降、一轮上升，合并请求 p99 近乎不变；不宣称尾延迟收益，也没有业务 p99 上限。
- 约束检查：四次性能任务均成功、0 错误，基线共 130688 请求、候选共 143489 请求；每次性能轮前后物理 NPU 0 均无其他进程，作业结束后复查两芯片无进程。10 实例 HBM after setup：基线约 6595.7 MB，候选约 6573.7 MB。2026-10-29 曾因全机占用暂停；2026-10-30 设备释放后恢复。曾有调试性完整 GE dump 约 5.8 GB 并被删除；此次关闭 dump，运行前文件系统可用约 23 GB。
- 是否接纳 / 最终是否纳入：接纳为固定 case-0000 的隔离实验优化 / 源码与可选入口已归档、默认配置未启用且未做迁入后性能验收；五例随机吞吐和最终执行图 profiling 不在本轮结论内。
- 后续行动：若要交付正式 runner，先集成并回归；如需宣称随机业务收益，另测五例随机与实际业务分布。若需核对具体 kernel 消失，再采集有限范围的最终执行图或 profiling。
