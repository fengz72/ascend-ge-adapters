# OPT-015：八实例半核配置启用 GE `force_fp16`

## 1. 身份与状态

2026-10-27分配。父版本为100机器已验收的原图FP32、GE mode=0、8实例、每算子`12|24`核；候选只改变GE `precision_mode`为`force_fp16`，其余模型、外部IO、核数和实例数保持一致。状态：五例正确性与GE图核验通过，同卡双场景各两轮正式性能通过；第三轮被外部占用拦截，稳定性未测，**暂不接纳为交付配置**。执行设备为逻辑10/NPU5/Chip0；目标逻辑2有外部占用，不以其历史性能计算本次收益。

## 2. 问题与假设

99机器单实例的Cube FP16及自动混精已通过给定五例数值但未显示吞吐收益，不能推断100机器八实例半核下`force_fp16`的效果。更积极的FP16可降低计算或HBM开销，也可能增加Cast、降低精度或使整图吞吐下降。按实际图、五例完整输出和同卡性能验证。

## 3. 实现与回退

在prepare-only入口显式传`--precision-mode force_fp16`，GE Session继续用当前CANN9 runner支持的`ge.exec.precision_mode`；不改原始ONNX和权重，不改七个INT64加一个FP32输入及FP32分数输出契约。备份执行根设备身份后临时切到逻辑10，实验结束恢复逻辑2。回退策略为`must_keep_origin_dtype`。

## 4. 比较条件

同一100机器、容器、逻辑10、原始模型和五条样例。先用8实例`12|24`的FP32配置在新卡做固定`case-0000`与五例随机短轮对照；`force_fp16`先做随机五例至少2000请求完整分数与Top10（dense_id+1）压力，再做相同口径纯性能短轮。计时包含H2D、GE同步、全量D2H；精度门槛和expected不变，p99无业务硬上限。搜索若显示≥3%且超过同卡波动，再做独立复测、两场景正式验收和稳定性；否则保留搜索结论、不替换已验收配置。

## 6. 分析与决策

GE实际Build图（SHA256 `e749c3579cd2feb2d4affadd22617bf9b6fbb65775e573975b22ed0188086c53`）含4141个解析节点；144个MatMulV2、55个BatchMatMulV2、49个LayerNorm及25个SoftmaxV2的图张量描述符为FP16。Cast共37个，其中6个FP32→FP16、2个FP16→FP32；图中仍有少量FP32描述符。该证据说明编译图确实降精度，不证明内部累加精度。外部七个INT64加一个FP32输入以及FP32分数输出与原契约相同。

同卡搜索和前两轮正式对照都显示吞吐收益，但FP16 p99较FP32增大且正式轮波动明显。第三轮的第一个FP32作业在模型运行前被逻辑10外部进程占用门禁拦截（退出76）；未把不同卡混为同一轮。为遵循用户“空闲逻辑设备即可用”的约定，门禁增加目标PCI芯片检查能力且CPU回归16/16通过，准备在逻辑13重新做完整同卡对照；但切换前逻辑13也出现外部PID，随后16个逻辑设备全部有进程，切换被安全拒绝，没有提交逻辑13作业。后续逻辑10释放后完成[10/12实例各两轮固定case短轮搜索](../analysis/100-force-fp16-instance-scaling-20261027.md)，初次数据因波动较大未用于择优；随后[8/10/12各三轮无profiling正式复测](../analysis/100-force-fp16-instance-retest-20261027.md)显示10实例相对8实例吞吐中值仅+2.957%，低于5.000%波动门槛，12实例中值下降5.301%，故均不接纳。新实例数未做五例精度与稳定性验收，FP16八实例第三轮正式跨精度对照与600秒稳定性仍未完成，因此决定为**候选保留、不替换当前已验收FP32配置**。

## 7. 复现与证据

计划见[FP16八实例实验计划](../analysis/100-force-fp16-plan-20261027.md)，机器可读摘要见[本轮证据](../evidence/20261027-force-fp16-interim.json)。远端100项目`work/`保留五例完整分数、请求事件、纯性能、资源采样、图dump及前后双芯片门禁；作业名为`fp16-parent8-d10-{case0,random}-s1-20261027`、`fp16-half8-d10-{pressure,case0-s1,random-s1}-20261027`及`fp16-formal-d10-{fp32,fp16}-{case0,random}-r{1,2}-20261027`。第三轮`fp16-formal-d10-fp32-case0-r3-20261027`预门禁失败；首次图dump`fp16-graph-d10-20261027`因采集脚本预创建runner输出目录而在模型加载前退出1，修复后新作业`fp16-graph-d10-r2-20261027`成功。这两个失败均保留并计入设备占用账本，未纳入性能结果。
