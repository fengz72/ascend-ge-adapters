# OPT-018：单层 FusedInferAttentionScore 显式融合

## 1. 身份与状态

2026-10-29 完成首层验证。父配置是 100 机器原始 BGE ONNX、GE mode=0、`precision_mode=force_fp16`，候选只把 encoder layer 0 的 QK/Softmax/V 注意力子图替换为 `FusedInferAttentionScore`。代码位于 `tools/bge_fias_pass/`，暂存于隔离的 `merge-review-20261029` 工作副本，原始 ONNX 和交付 runner 未改动。状态：GE 图命中、运行及五例精度均已验证；单层吞吐收益未证实，**暂不纳入交付**。

## 2. 问题与假设

此前 GE Build 图仍保留 24 组 `BatchMatMulV2 → Add(padding mask) → SoftmaxV2 → BatchMatMulV2`。此候选先只改首层，以验证已安装 CANN 9.0.0 的 FIAS 接口、mask 布尔语义及动态 shape，避免一次替换 24 层后无法定位误差。方法来自本工作流的性能分析和 `docs/bge/analysis/fusion-independent-audit.md`；目标 schema 以容器内 `ops_proto_legacy.h` 为准。

## 3. 实现与回退

pass 从三个 BSND `Reshape` 接 Q/K/V；原图 Q、K 各乘 `sqrt(1/sqrt(64))`，候选设 FIAS `scale=0.125`，`num_heads=num_key_value_heads=16`，`input_layout=BSND`，`sparse_mode=0`。原图 `Where_2` 的 BOOL 条件为 1 时选择 `-FLT_MAX`，因此直接接到 FIAS `atten_mask`，真值表示屏蔽。保留上游 `Expand_1` 及其动态 shape 逻辑，不从原始 INT64 keep-mask 另造三角矩阵。FIAS 输出替换原末端转置的 BSND 输出。pass 在 `kAfterBuiltinFusionPass` 插入节点；GE 后续 `force_fp16` 阶段把 Q/K/V 和输出改成 FP16，mask 保持 BOOL。K/V 动态输入必须插入端口 1/2，mask 为端口 4。移除实验性 `BGE_FIAS_PASS_SO` 环境变量即回退；原图不变。

## 4. 比较条件

目标 100 / `hejun-cann9-bge` / Ascend910_9382 / CANN 9.0.0，原始输入为五条 `sample_inputs.json`，已与 CPU 和 `expected_outputs.json` 比较 Top10 ID、顺序、分数（dense ID +1）。五条样例的 `attention_mask` **全部为 1**，另测试了 `[1,1,1,1,0,0]` padding 和全 0 mask 边界。性能仅进行固定 `case-0000` 的 30 秒探索轮，10 实例、每算子 `12|24` 核、无 profiling，计时包含 H2D、描述符、GE 同步和完整 D2H。p99 上限尚未给出。未完成随机场景和正式多轮性能验收。

## 6. 分析与决策

首次隔离 build 成功。随后排除环境阻断：过长的路径使 CANN `multiprocessing.Manager` 的 AF_UNIX socket 初始化失败，改用短 `TMPDIR`；父 Python 进程预加载 pass 会破坏 forkserver，改为仅原生 GE 子进程预加载并在启动 CANN worker 前清除。一次完整 GE 图 dump 重复写出大权重产生 100GB 以上文件，已取消并删除实验 dump；只保留不含权重的图结构和 pass 日志。

对 FP16 GE Build 图的核查显示：内置转置优化可能把末端节点改名为 `PartitionedCall_...Transpose_3_Transpose_*`，并把所有动态 shape 维度标为 `-1`。候选 matcher 支持此形式，用首层确切节点名约束模式。初版把 K/V 动态输入追加到端口 29/30，导致 lowering 找不到描述符；改为按 IR 索引 1/2 插入。再往后放在 `kAfterOriginGraphOptimize` 虽能 `CompileGraph`，`LoadGraph` 的内部分区却缺失 `NetOutput`（主图 pass 前后均保留 1 个）；改回较早的 `kAfterBuiltinFusionPass` 后模式命中、优化后实际 FIAS 描述符为 FP16、加载和推理成功。

五例业务精度通过；普通 padding 也通过。全 0 mask 在 CPU FP32 有限，在 FIAS 与未融合的 GE `force_fp16` 均非有限，因此该 FP16 路线必须约束每行至少一个可见 key，若业务要求全 0 mask 须另做兜底。有效的 30 秒固定 case 轮次都零请求错误，但原图一轮与候选两轮不构成稳定 A/B，候选两轮自身相差约 4.6%；**不接纳单层融合的吞吐收益主张**。若以后推广 24 层，另立优化点并重新做五例精度、随机回放与正式多轮性能验收。
