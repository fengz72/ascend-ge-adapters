## 2. 共同口径

各篇只写本次实际参数与结果；下列口径一次定义，不再逐篇重复。

**父基线。** 99 主机首次可信 FP32 全核单实例基线为 QPS 中位数 175.321044、合并 31312 请求 p99 6.819411 ms、轮间相对极差 11.4495%，取三轮 ≥60 秒且 ≥10000 完成的中位数。100 主机各场景的父基线在对应篇内单独给出（单实例正式三轮、八实例同场景或上一编号），不跨主机、不跨场景拼接。100 原图八实例半核固定 `case-0000` 三轮中位 586.386711 QPS、合并 p99 14.147862 ms，为 OPT-012～014 的父版本。

**计时边界。** 端到端窗口为 H2D 输入搬运 + 描述符设置 + GE 完成同步 + 完整 FP32 scores D2H 就绪；纯性能轮 capture/profiling=false，压力采集另做，采集数字不作性能值。

**预热与设备。** 每实例每 case 预热 10 次；99 阶段逻辑设备 10（NPU5/Chip0，PCI0000:89:00.0），100 阶段按各篇标注（逻辑 2 或临时切至空闲逻辑 10）。

**门禁与身份。** 每个设备作业前后执行 proc-mem 设备门禁，并核对输入身份、运行身份与测量 binary 身份；作业失败、超时、清理异常或外部占用均不产生有效性能值。OPT-001～009 共用冻结测量 binary SHA256=`8efca50a62a7f569032345259d6e7813da428023903e4674d77de92bc7ac630d`。

**工作负载与判据。** 工作负载为给定五例 B1 等概率闭环回放，源模型/权重、`sample_inputs.json`、`expected_outputs.json` 及阈值均不改变；未设 p99 硬上限，但必须报告延迟变化。任务只验证能否提高包含输入输出搬运的成功吞吐，不得由算子数量或数据类型推算实测收益。

**搜索轮与正式轮。** 30 秒/≥2000 请求的搜索只用于筛选；正式轮为三轮 ≥60 秒/≥10000 请求，取中位数并按合并请求 nearest-rank 计算 p99。搜索相对差值只是观察，无统计显著性声明；不同容量点的 p99 不作同负载延迟收益。收益需超过 3% 且超过基线/候选轮间相对极差的较大值，才算越过实际波动门槛；该门槛是约定判据，不是统计置信区间。

**独立数值报告。** 每项数值结论引用独立报告；V1 失败不能用 V2 成功覆盖，不同候选、不同主机、不同场景的精度与性能结论不互相替代。

**汇总规则。** 最终汇总保留本记录，无论提升、退化或失败；最终整体提升不累加逐点百分比。

## 3. 七节结构契约

每篇顶层固定七节，编号与职责为：

1. **身份与状态** —— 分配日期、父版本、设备身份、当时的接纳状态；
2. **问题与假设** —— 本次要检验的假设与失败判据；
3. **实现与回退** —— 改动内容、回退路径、测量身份；
4. **比较条件** —— 本次实际参数（实例数、核上限、精度模式、轮数、seed、作业名），通用口径引用第 2 节；
5. **基线与优化后结果** —— 基线/候选表、精度与稳定性数字；
6. **分析与决策** —— 对 §5 的解释与最终接纳/不接纳结论；
7. **复现与证据** —— 计划、作业名、命令、原始证据与报告链接。

OPT-012 之后的补充验收与复测按职责回填进上述七节：最终决策与接纳状态写入 §1 和 §6，复测数据表与证据指针写入 §5 和 §7，不再新增顶层节。`[100 最终测试计划](../analysis/100-final-test-plan.md)` 的文档核对契约为「每个 OPT 恰好一行七列」，指交付文档的表格行，不要求各篇 §4 独立成文。
