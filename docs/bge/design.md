# BGE 推理适配与吞吐优化设计

需求见 [brief.md](brief.md)。本文件只保留仍然成立的约定：接口与数值门槛、测量与判定口径、设备与预算约定、执行入口。

## 1. 接口与数值门槛

| 材料 | SHA-256 |
|---|---|
| 原始 model.onnx | `2080f8762d9f8de50f8ec22f6a560453d3052d13012ea6fe7c199197962b3ba0` |
| sample_inputs.json | `66571de2fa8c6a97e52a196a957801ab09b429751ba9cfb94712bb32c660b194` |
| expected_outputs.json | `4765cc2b9dac9d2f523f9a684a81082d3b943caaff1fd2c4db90cfdf1b375384` |

ONNX 为动态接口，包含 3137 个节点、400 个 initializer。本轮支持和验收范围收敛到提供的五条样例及其重复、重排和并发，不从动态符号推导任意 shape 都已受支持。

| 输入/输出 | dtype | 图接口 | 本轮范围 |
|---|---|---|---|
| input_ids、attention_mask | INT64 | `[B,S]` | B=1，S 为 6/9/8/13/8；mask 为 0/1，有效维度一致 |
| long_cid3_raw、long_action、long_time_bucket | INT64 | `[B,L]` | B=1，L=128，三者维度一致 |
| stat_dense_raw | INT64 | `[B,20]` | 按提供样例，合法索引由原样例固定 |
| stat_ratio | FP32 | `[B,20]` | 有限数值，保持原始值 |
| stat_count | INT64 | `[B]` | 0～20，沿用样例 |
| scores | FP32 | `[B,10112]` | 每请求完整输出到 Host；不只回传 Top10 |

输入为每请求 3416～3528 字节，输出为 40448 字节。数据量小只构成分析线索，不能据此宣称瓶颈或收益。样例只有四种文本 shape、一个行为长度；未覆盖 B>1、其他文本/行为长度、空输入和越界输入的设备语义。框架现有的无效输入检查另作 CPU 回归，不把异常输入结果混入正常性能分布。

参考独立于候选：使用原始模型的 CPU ONNX Runtime 完整分数，以及用户提供的 expected Top10。CPU golden 绑定模型/输入/ORT 版本和配置；不由候选生成 expected。完整分数门槛保持 cosine≥0.9999、relative L2≤0.001、max absolute error≤0.001；Top10 的 `dense_id=输出下标+1`，ID 和顺序精确一致，分数 atol=0.001、rtol=0，同分采用稳定下标顺序。NaN/Inf、输出数量或 shape/dtype 错误直接失败，不改阈值或 expected 来通过。

## 2. 测量与判定口径

- **请求定义**：B=1，每实例最多一个在途请求，闭环饱和施压，下一请求在前一完整输出就绪后发送。固定 case 池必须实际只有一条；随机池实际五条。保存每请求 case_id 和场景/计划身份；不能由随机日志的 case-0002 分组时延推算固定场景 QPS。报告各场景总体样本数、成功率、吞吐、p50/p99；随机另列分 case 统计。
- **计时起止**：Host 输入已备好，首次 H2D 前取单调时钟；包含描述符、全部输入搬运、GE 完成同步和完整 scores D2H；Host 输出可安全读取后取结束时间。文件读取、分词、CPU 参考和报告落盘在外；服务网络、排队与批处理等待不在本轮范围。历史 bench 入口的计时止于 H2D/GE 同步、D2H 只在 capture 路径发生，infer 又强制单实例、只收 instance0 输出；正式测量必须把完整 D2H 纳入计时，并在多实例压力中逐请求关联 request_id、instance_id、case_id 与完整输出，不能只核对调用数。
- **缓存**：原始五输入可预装 Host 内存，模型/权重常驻；每请求仍执行真实 H2D、GE、D2H，不使用结果缓存或设备输入命中代替执行。每实例对参与场景的每个 case 预热至少 10 次，预热包含 D2H；编译、加载和预定预热不计性能，但计设备占用。
- **窗口**：搜索每配置每场景至少 30 秒且至少 2000 请求；正式基线和冻结后验收每场景每轮至少 60 秒且至少 10000 请求，各三轮。测量分别最多 180/300 秒；达到时间上限仍不足请求门槛时标为统计不足，不能降低门槛冒充验收。
- **完成统计**：保存同一时钟的测量窗口起止、请求开始/结束、case/instance/request_id、状态和分项。主 QPS=`窗口内成功完成的请求数÷窗口实际秒数`；窗口截止后停止新发请求并排空，同时报告退出时在途数、完整请求延迟和排空时长，不把排空后的请求总数除以发送窗口冒充稳态容量。
- **p99**：固定/随机分别统计，不合并两场景延迟；最近秩 `sorted[ceil(0.99*N)-1]`，总体与分 case 分开，错误/超时不能静默剔除。跨轮保留各轮值和合并原始延迟分布，不平均 p99。无 p99 上限，结论中只报告观察值。
- **压力与稳定性**：冻结配置至少 2000 请求，保证每实例每个 case 至少出现 20 次，覆盖重复、交错和四种文本 shape 切换；连续 10 分钟 0 错误/超时/丢失/重复响应；前/后各两分钟资源中位数比较，RSS 增量不超过 max(128MiB, 初值 5%)，HBM 增量不超过 max(64MiB, 初值 1%)，并检查连续增长趋势。另完成三轮加载→混合请求→销毁并确认进程、锁与设备上下文释放。
- **有效性**：0 错误/超时、0 未归档请求；闭环并发有界、结束全部排空，10 秒窗口吞吐无持续下降。外部设备任务、Host 构建争抢或 profiling 使轮次不可比时判无效。profiling 独立采集，不计入正式收益。
- **波动**：正式收益采用独立验收三轮吞吐中位数，合并 p99 另列。吞吐提升不足 3%，或不超过基线/候选轮间相对极差中的较大值，记录观测差值并判“无显著变化”。按预算交错复测消除漂移，不无限追加轮次。
- **范围**：B=1 的五条给定样例只描述该闭环回放负载，不外推业务流量、生产分布或低精度边界验收。

## 3. 设备与预算约定

设备不固定：哪个逻辑设备空闲且可独占就用哪个，启动前重新核查逻辑编号到 PCI BDF/物理芯片的映射。每轮前后检查进程、HBM、宿主 PID 与同卡邻芯片的实际占用和释放，状态不明或出现外部任务时暂停性能测试，不终止他人进程。正式 A/B 尽量同卡交错，跨卡对照须记录差异并复测。

每个设备作业有有限超时并逐任务登记实际锁持有与设备开始/结束；设备时间与配置数不设总量上限，只做累计占用记账。编译/加载、预热、正确性、失败与清理、profiling 和复测都计入占用。

未探索的更大并发不声称最优；停止上探须有吞吐平台/回落、HBM 不足、正确性失败或实际资源限制的证据，外部占用或单作业失败不能单独证明已达上限。
