## 5. 边界与后续验证

模型只有五条给定样例，未覆盖更大 shape、生产流量或服务排队；没有 p99 业务上限，不能承诺线上延迟。第 3 轮固定候选原作业收到 SIGTERM，发送者未知；其后用相同配置和新作业名补测成功，失败占用仍计入预算。100 的全机 load average 偏高，但多数正式轮的 Host CPU busy 采样较低；第 1 轮随机候选出现长尾，不能单凭有限采样把原因归为外部进程。RSS 在 600 秒内单调上升，符合 runner 逐请求保存记录的实现，但**没有证明长期服务运行时 Host 内存形成平台或完全无泄漏**；如投入长期服务，应以不持续积累请求记录的生产 runner 和实际业务分布另做长时验证。完成原交付稳定性后累计设备占用 5765.941167 秒、实际唯一配置 12/12；此后改用空闲可独占设备继续测得累计 7216.234463 秒，设备时间与配置数不设总量上限，逐作业明细见[证据摘要](evidence/20261027-instance-scaling-summary.json)。
