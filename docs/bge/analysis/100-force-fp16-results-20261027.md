# BGE `force_fp16`：100机器阶段性结果

日期：2026-10-27。执行环境为100机器`hejun-cann9-bge`容器、项目根`/export/home/ext.hejun23/workspace/bge-opt-100`。逻辑2被占用后，先核查并使用当时空闲的逻辑10/NPU5/Chip0，同卡Chip1纳入锁与前后门禁。所有本页FP32/FP16对照均在逻辑10，原ONNX、GE Session mode0、8实例、每算子`aicore_num=12|24`、无自定义融合插件，仅`precision_mode`不同。计时包括H2D、GE完成同步、全量D2H与Host输出分配；不包括文件读取和服务排队。

## 正确性和编译图

`force_fp16`五条给定样例等概率回放2007请求，每个实例×case至少36次；全部请求的完整10112维分数、Top10 ID（`dense_id=下标+1`）、顺序、分数及请求关联通过原CPU阈值。最大绝对误差0.000568092、relative L2 0.000814097、Top10最大分数误差0.000568094；全部分数有限。外部输入保持七个INT64加一个FP32，输出仍按FP32分数契约校验，未修改ONNX和权重。

另将归档的FP32八实例压力输出（逻辑2）与FP16八实例压力输出（逻辑10）按五例直接对比。每个case在各自2007请求回放中输出逐位一致；逐case取第一条完整10112维向量时，FP16相对FP32的最大绝对差为0.000587523、相对L2最差0.000736365、cosine最小0.999999765。五例Top10 ID和顺序全部相同，Top10分数最大差0.000587523。这个直接差值与各自相对CPU reference的误差是不同口径；逐例数字与输出哈希见[直接比较证据](../evidence/20261027-force-fp16-vs-fp32-direct-output.json)。

单实例、固定`case-0000`的GE Build图（SHA256 `e749c3579cd2feb2d4affadd22617bf9b6fbb65775e573975b22ed0188086c53`）有4141个解析节点。144个MatMulV2、55个BatchMatMulV2、49个LayerNorm、25个SoftmaxV2和24个Gelu的张量描述符为FP16；37个Cast中6个FP32→FP16、2个FP16→FP32。此图证明这一路径的图张量确实降精度，无法仅据描述符断言内部累加精度；八实例五例精度压力与该单实例图采集是分开的作业。首次图采集脚本误建runner输出目录，作业在加载前退出1；新作业修复后成功，两个作业均留档。

## 同卡性能

30秒/至少2000成功请求的纯性能搜索结果如下。每个场景输入与seed成对一致；capture和profiling不在性能作业中开启。

|场景|FP32 QPS / p99|`force_fp16` QPS / p99|QPS变化|
|---|---:|---:|---:|
|固定`case-0000`|577.179 / 14.379ms|868.355 / 11.361ms|+50.45%|
|五例随机|593.252 / 14.132ms|796.624 / 19.281ms|+34.28%|

按预先约定，另做每场景三轮、每轮≥60秒且≥10000成功请求的FP32/FP16交错正式对照。前两轮均通过独立请求事件重算、身份与设备门禁；第三轮在首个FP32作业预门禁发现外部PID，退出76且未运行模型。下表中值仅是**两轮阶段性观察**，并非三轮正式验收结论。

|场景|FP32 QPS 两轮（中值）|FP16 QPS 两轮（中值）|QPS阶段性变化|FP32 / FP16 p99两轮中值|
|---|---:|---:|---:|---:|
|固定`case-0000`|583.632、584.865（584.249）|750.482、856.247（803.364）|+37.50%|14.498 / 17.946ms|
|五例随机|582.940、590.719（586.829）|710.208、766.071（738.140）|+25.78%|14.994 / 20.272ms|

FP16两轮QPS相对极差分别13.17%和7.57%；FP32分别0.21%和1.33%。即使吞吐方向一致，FP16的p99及轮间波动需要继续观察。当前无业务p99硬上限，不能据此宣称满足线上延迟目标；也不能只选搜索短轮或第二轮作为稳定收益。

## 状态和恢复

第三轮被拦截时逻辑10的Chip0有外部进程，同卡Chip1虽空，原双芯片门禁不允许本任务启动。用户已允许使用任一空闲逻辑设备，因此为后续作业新增只对实际运行PCI芯片检查独占/释放、同时记录邻芯片占用的可选门禁，16项CPU回归通过。计划在逻辑13重新建完整同卡对照，但切卡前该逻辑设备也出现外部PID；随后复核16个逻辑设备全有进程，没有提交逻辑13作业，项目身份保持逻辑2。未执行FP16候选的600秒稳定性和精度策略变更后的实例数重搜。当前交付配置继续为已验收FP32八实例半核；FP16为待完成候选。

设备独占恢复后，以新作业名重做第三组同卡FP32/FP16固定及随机正式对照，并检查各轮p99、资源与释放；随后搜索FP16的实例数，若形成新最佳配置再做五例压力、双场景正式验收及600秒稳定性。所有结果、图摘要、失败门禁及文件哈希在[机器可读证据](../evidence/20261027-force-fp16-interim.json)，固定优化记录在[OPT-015](../experiments/OPT-015.md)。
