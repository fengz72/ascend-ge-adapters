## 4. 正式验收与数值预算门禁

固定与随机、基线与最终候选、各三轮，共 **12 个正式性能 run**。已在 T2 完成且身份/条件可比的正式基线轮次只算一次，不重复收费；保留最终冻结后与基线的交错观察以排查漂移。若 T2 后环境/软件或测量版本变化导致不可比，重做所需基线并计费。

最低预留 **3000 秒（50分钟）** 不代表任何加载速度下都够用。每次设备任务后重算：

```text
预计每个剩余正式run = 加载/编译/预热/清理保守值
                    + max(60秒, 10000 / 当前该场景保守QPS)
验收保留额 R = max(剩余50分钟子项保留额,
                  1.2 × [剩余正式run费用 + 全五例压力费用
                         + 三轮加载销毁费用 + 600秒稳定性及其加载/清理费用])
启动搜索条件 = 剩余预算 - 本次任务最坏允许费用 >= R
```

这里的“剩余50分钟子项保留额”是从最初3000秒中扣除**已经完成且有效的正式验收子项实际费用**后的余额；搜索、无效轮次、profiling不能核销验收保留额。估算还需按实际低吞吐场景、最慢加载、warmup和受管清理更新；`10000/QPS > 300秒` 或测量达到300秒仍不足10000时，该轮标统计不足，不能降低门槛。

保守资源分配起点：

|用途|初始设备时间封套|
|---|---:|
|T2＋T8 双场景正式基线/最终、压力、生命周期、稳定性与余量|至少3000秒，动态上调|
|T1 本机原始正确性|最多120秒目标|
|T3 固定case融合交错与有限profiling|最多600秒目标|
|T4 八实例全核复现|最多360秒目标|
|T5 半核八实例|最多360秒目标|
|T6 融合×较优并发|最多420秒目标|
|未分配机动|723.320090秒；只在完整验收预留仍满足时使用|

封套合计等于5583.320090秒。这不是承诺每阶段都能在目标内完成；达到封套或出现加载变慢时先缩减后续搜索，优先完成冻结验收，不能借用未获授权的时长。若程序 timeout 配置高于阶段封套，主控仍须用总预算门禁和可清理的任务截止，防止单次任务侵占验收额度。

冻结验收继续沿用设计：

- 固定/随机各三轮正式性能，分别计算QPS中位数、总体/分case延迟，跨轮p99用原始延迟合并，禁止平均p99或混合两场景。性能轮 capture/profiling=false，每请求仍全量D2H。
- 最终五例输出关联压力≥2000请求，每个实例×case≥20，检查完整scores及Top10；若8实例则40个组合都覆盖。固定性能不能替代此项。
- 三轮真实加载→混合请求→销毁，保存进程/锁/上下文释放，可复用真实完成的冻结配置job生命周期证据；未执行接口不能写PASS。
- 冻结配置连续随机五例至少600秒；每10秒记录Host RSS、HBM和成功吞吐，0错误/超时/丢失/重复响应。资源增长门槛继续用原设计，不用稳定性计数冒充逐请求精度比较。
- 0错误、全部排空、真实设备前后清洁、无外部干扰；正式收益低于3%或不超过基线/候选相对极差较大者，写“无显著变化”。不同容量点p99变化仅作观察。

## 5. 停止、回退与记录

1. 外部占用、映射或独占性不明、锁失效、同卡共享资源干扰：不启动/立即停止后续性能任务，保留证据，用户外部进程保持不动。
2. 任一候选完整输出、Top10、请求关联、NaN/Inf、接口或清理失败：停止该候选，回退已验证父项；失败记录保留。仅可确认的基础设施失败允许原配置一次重试，费用照计。
3. 16实例旧搜索已SIGKILL且没有有效性能；本轮不重启盲目更高并发。两次同类资源失败停止该方向，不无证据写OOM根因。
4. T5未超过波动，不自动扩展四分核网格；T6若有资源效率依据可保留一次。两轮细调无可信收益、名额达到12，或费用触及R，停止搜索并冻结最好已通过点。
5. T3无足够profiling、对应关系或重复测量时，只写“原因未确定”；不由节点变少、F32/FP16描述符、kernel名称中的high_performance或单轮平均值推断性能因果。
6. 每个OPT仍七节固定记录，既有OPT追加100本机场景/run身份且不覆盖99数值；新配置由主控另编号。最终每项一行列一句话内容、同场景基线、候选、增减幅度、是否接纳和原因，失败/无收益/未运行完整保留。
