# BGE 在 100 机器上的实例数上探（2026-10-27）

## 1. 条件与预先定义的筛选规则

主机 100、容器 `hejun-cann9-bge`、项目根 `/export/home/ext.hejun23/workspace/bge-opt-100`。逻辑设备 2 = NPU1/Chip0 / PCI `0000:99:00.0`，同卡 Chip1/PCI `0000:9B:00.0` 也加锁及前后门禁。保持原始 FP32 ONNX、GE Session mode=0、每算子 `aicore_num=12|24`、无 Slice 改写与自定义融合插件；固定 `case-0000`、batch1、每实例单在途。计时包含 H2D、GE 完成同步和完整 D2H。吞吐上探按 10→12→16 实例顺序，后续根据实测收益和 HBM 余量决定是否继续或在相邻点加密。

起点是 [case-0000 正式复测](100-case0-performance-20261027.md)：8 实例三轮 QPS 582.365/586.387/600.133，中位 586.387、相对极差 3.03%，合并 p99 14.148 ms。

**预先定义**的筛选规则：候选 QPS 相对 8 实例三轮中位数或当前更优点提升至少 3%，且超出轮间相对极差，才作为明确增益进入下一档；接近或低于门槛时复测相邻点，不凭单轮下降宣称平台。HBM 余量不足、加载/执行失败、外部占用时停止或回退并核查原因；不把未明 SIGKILL 自动判为 OOM。没有 p99 业务硬上限，但持续报告 p99 和错误。每个新实例数单独分配 OPT 和配置键、保留失败；搜索轮固定 `case-0000`，至少 30 秒/2000 请求。最终高吞吐候选还须独立冻结验收。

旧配置名额 12/12 已用完，原 7200 秒设备时间上限在本轮开始时尚余 973.758519 秒；用户改为“哪个设备空了用哪个设备”，这两个总量上限不再阻断搜索。已用时间、每档配置和失败仍逐作业记账。每个作业保持有限超时、独占门禁与释放检查；同卡对照优先，跨卡则记录环境差异并复测。

## 3. 结论与停止依据

在 16 实例处观察到两轮吞吐回落（相对 8 实例 +0.015%、相对 12 实例 −2.03%）且 p99 增至约 29.6–29.8 ms，HBM 仍远未用满，因此按**吞吐平台/回落**停止继续上探，不把 16 实例称为 HBM 或硬件上限，也不沿用 99 机器 16 实例全核 SIGKILL 的未明原因。

本轮结束时推荐仍为 8 实例（FP32 阶段交付配置），其五例精度压力、双场景三轮和 600 秒稳定性见 [100 交付报告](../delivery-100.md)。10/12/16 三个新点未达接纳门槛，也未做五例完整输出与稳定性验收。
